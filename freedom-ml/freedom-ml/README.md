# Freedom Investment Challenge — ML-отбор недооценённых акций

Модель «справедливого мультипликатора» для поиска недооценённых американских компаний и прогноз волатильности GARCH для распределения портфеля. Проект сделан для кейс-конкурса **Freedom Investment Challenge** (ноябрь 2026).

> *Fair-multiple ML screen (numpy MLP with hand-written backpropagation, gradient-checked) over S&P 500 + S&P 400, plus GARCH(1,1) volatility forecasting for portfolio weights.*

## Что делает код

**Часть A — отбор недооценённых компаний.** Модель учится на ~680 компаниях S&P 500 и S&P 400 предсказывать, какой EV/EBITDA рынок обычно платит за данный набор характеристик бизнеса: рост, маржу, рентабельность, долг, риск и сектор. Если фактический мультипликатор сильно ниже предсказанного, а бизнес проходит проверку на «ловушку стоимости», компания становится кандидатом в недооценённые.

**Часть B — риск и веса портфеля.** Сравниваются три способа прогнозировать волатильность (историческая, EWMA, GARCH(1,1)) на данных, которые модель не видела. Лучшим методом строится прогноз на 12 месяцев, а корреляции оцениваются со сжатием Ledoit-Wolf. На выходе — веса портфеля обратно пропорционально риску и портфель минимальной дисперсии.

## Результаты (прогон 2 ноября 2026, после закрытия торгов)

**Качество моделей на компаниях, которых модель не видела (5-кратная кросс-валидация):**

| Модель | R² | Типичная ошибка мультипликатора |
|---|---|---|
| Ансамбль (Ridge + бустинг + MLP) | 0,413 | 36,4% |
| Нейросеть (MLP, backprop) | 0,387 | 37,4% |
| Градиентный бустинг | 0,380 | 37,4% |
| Линейная регрессия (Ridge) | 0,269 | 41,4% |
| Медиана сектора | 0,182 | 42,8% |

Нейросеть заметно точнее линейной регрессии: связь между качеством бизнеса и мультипликатором нелинейная. Ошибка ~36% слишком велика для целевой цены, поэтому модель используется только для **отбора** кандидатов. Целевые цены считаются фундаментально (P/E, DCF, P/TBV) в отдельной Excel-модели.

**Воронка отбора:** 903 компании → 680 с данными (без банков, страховщиков и недвижимости) → 639 проходят правила конкурса → 491 без признаков ловушки стоимости → 133 дешевле справедливого мультипликатора на 20% и больше.

**Прогноз волатильности (проверка на 2025–2026 гг., QLIKE — меньше лучше):** GARCH(1,1) — 0,248, историческая за 63 дня — 0,292, EWMA — 0,346.

**Проверка градиентов backpropagation:** максимальная относительная ошибка против численной производной — 1,5 × 10⁻⁷.

## Метод

### Данные
- Состав индексов — из Википедии (запасной вариант — CSV с GitHub), фундаментальные показатели и цены — Yahoo Finance через `yfinance`.
- Капитализация на дату фиксации = капитализация Yahoo × (цена на `PRICE_DATE` / текущая цена). Так учитываются все классы акций: у Alphabet, Fox, News Corp поле `sharesOutstanding` содержит только один класс.
- EV на дату = капитализация + чистый долг (EV Yahoo − капитализация Yahoo).

### Целевая переменная и признаки
- **Цель:** `log(EV / EBITDA)`. Логарифм нужен, чтобы ошибка в 20% весила одинаково для 5x и для 30x.
- **Числовые признаки** (обрезаны по фиксированным границам, без утечки данных): рост выручки, рост прибыли, валовая маржа, маржа EBITDA, операционная маржа, маржа FCF, ROE, ROA, чистый долг / EBITDA, бета, логарифм выручки.
- **Категориальный:** сектор (one-hot).
- **Цена акции и капитализация в признаки не входят** — иначе модель «подглядывала» бы в ответ. Размер компании меряется выручкой.
- **Исключены:** Financial Services и Real Estate (для них EV/EBITDA не имеет смысла), компании с EBITDA ≤ 0 и выбросы с EV/EBITDA вне диапазона 2–80x.

### Модели
- **Медиана сектора** — ориентир без обучения.
- **Ridge** — `RidgeCV`, α из `logspace(-2, 3, 20)`.
- **Градиентный бустинг** — `HistGradientBoostingRegressor` (400 итераций, learning rate 0,04, 15 листьев, минимум 20 объектов в листе, L2 = 1,0).
- **Нейросеть (MLP)** на чистом numpy, без PyTorch:
  - архитектура: вход → 64 (ReLU) → 32 (ReLU) → 1, инициализация He;
  - функция потерь — MSE + L2 (1e-4); dropout 10%;
  - оптимизатор Adam (lr 1e-3), мини-батчи по 64;
  - ранняя остановка: 15% выборки на валидацию, терпение 40 эпох, максимум 600;
  - среднее из 3 запусков с разными начальными весами;
  - прямой и обратный проход написаны вручную, градиенты проверяются численно (`gradient_check()`).
- **Ансамбль** — среднее Ridge, бустинга и MLP.

Предобработка (медианное заполнение пропусков, стандартизация, one-hot) обучается внутри каждого фолда. Прогноз для каждой компании — out-of-fold: его делает модель, которая эту компанию не видела. Для отбора берётся модель с наименьшей ошибкой. Важность признаков считается перестановкой (`permutation_importance`).

### Фильтры
- **Правила конкурса:** капитализация ≥ $2 млрд, среднедневной оборот за 3 месяца ≥ $3 млн, на бирже ≥ 3 лет, только обыкновенные акции, без запрещённых отраслей (табак, алкоголь, азартные игры, уголь, аэрокосмос и оборона).
- **Проверка на ловушку стоимости:** FCF > 0, чистый долг / EBITDA ≤ 4, выручка не падает больше чем на 5%.

### Волатильность и корреляции
- **GARCH(1,1)** реализован самостоятельно: метод максимального правдоподобия (`scipy`) с variance targeting.
- **Сравнение с EWMA (λ = 0,94) и исторической волатильностью за 63 дня:** каждый месяц 2025–2026 гг. строится прогноз на 21 торговый день только по данным, доступным на тот момент; метрики — QLIKE и относительная ошибка.
- **Прогноз на 12 месяцев** строится лучшим методом.
- **Корреляции** — дневные доходности за 2 года, сжатие Ledoit-Wolf.
- **Веса:** обратно пропорционально волатильности, плюс минимальная дисперсия с лимитами 10–30% на бумагу (SLSQP).

## Ограничения
- Модель смотрит на показатели за прошлые 12 месяцев. Циклические компании на пике (сырьё, память, нефть, НПЗ) выглядят дешёвыми, но это ловушка. Топ модели всегда нужно разбирать вручную.
- Модель не видит качественных факторов: смена менеджмента, судебные иски, технологические угрозы.
- Искажённые входы дают искажённый результат. Например, у Alphabet в 2026 г. FCF около нуля из-за рекордного капекса, а прибыль искажена переоценкой доли в SpaceX, поэтому для него модель неприменима.
- Данные Yahoo Finance бывают неполными и иногда содержат ошибки. Ключевые цифры стоит сверять с отчётами компаний (10-Q, 10-K на sec.gov).
